## Plan
What I found:
- The stack is in `us-east-1`, where a CloudFront web ACL (scope `CLOUDFRONT`) must live, so it fits in the same stack. No second stack and no cross-region reference are needed.
- **The app's own limits:** 300 reads a minute per user and 120 per agent key, plus sign-in and sign-up per address (`config/safeguards.json`). The WAF is the coarse outer layer: it stops floods and known-bad traffic before they reach the platform, and must never trip for a normal user.
- **Cost:** about $9 a month for dev. That is $5 for the web ACL, $1 per rule (4 rules) and $0.60 per million requests; the three AWS managed rule groups below carry no extra subscription. WAF was planned (T-06, M2-10) but is a new AWS service in the stack, hence this note.
- **Permissions:** CDK's execution role creates it, so the admin needs to add nothing.

Steps:
1. **Web ACL in `aia-stack.ts`** (scope `CLOUDFRONT`, default allow), attached to the distribution:
   - **AWS Common Rule Set (`AWSManagedRulesCommonRuleSet`).** Its body-size rule (8 KB) is set to count-only, so a large MCP or settings request is never cut off; it is logged in metrics instead.
   - **Known Bad Inputs (`AWSManagedRulesKnownBadInputsRuleSet`).**
   - **Amazon IP Reputation List (`AWSManagedRulesAmazonIpReputationList`).**
   - **A per-address ceiling:** 3,000 requests per 5 minutes per IP, about 600 a minute, twice a user's app limit, so scroll-back bursts and a busy chart never hit it. Over it, a **429** with a JSON body in the app's own error shape (`{"error":{"code":"rate_limited",...}}`), so the chart shows it like any other limit.
   - CloudWatch metrics and sampled requests on (free). No full request logging (it costs extra); it can be added later.
2. **Ceiling per environment:** `wafRequestsPer5Min` in `environments.ts`, 3,000 for dev.
3. **Template tests:**
   - the web ACL is on the distribution, with exactly these four rules;
   - default allow; the 429 body;
   - the body-size rule is count-only.
4. **Deploy to dev and check:**
   - normal traffic passes (the chart page, `/health`, sign-in);
   - a burst of about 3,500 `/health` requests from this machine is answered 429 once WAF catches up (usually within a minute), and lets through again after the window. This briefly blocks only my own IP.
5. **Docs:**
   - architecture (AWS, rate limits);
   - T-06: the WAF half done; it stays open for the starter numbers;
   - card handoff.

Not in this task:
- full WAF request logs to CloudWatch (about $0.50 per GB);
- country blocking or bot control (paid);
- tuning the ceiling with the client (with T-06).
