## Plan
What I found:
- An indicator's internals are its state (what `init` returns and `step` passes on), its code, and values before rounding. The engine keeps state in its output cache (Redis), never in a response, and rounds outputs to display precision. Nothing checks that from the outside yet.
- The e2e server already registers a test-only indicator (`settingsDemo`). The browser may import only the contract and the kernel (lint), but nothing checks the built bundle.

Steps:
1. **A canary indicator** (test-only, `apps/platform/src/leak-canary-indicator.ts`, registered in the e2e server and the server test). Its internals carry unmistakable markers:
   - a state field named `leakCanaryInternalState`;
   - an internal running value with many decimals (for example 1234.567891234), so an unrounded value is easy to spot;
   - a string constant used only inside `step`.
   It draws one line, rounded to the instrument's precision.
2. **Server test** (`apps/platform/src/leak.test.ts`):
   - calls `GET /indicators`, the settings check, `POST /indicators/:id/outputs` (with and without a forming bar), and the MCP tools `list_indicators` and `get_indicator_output`;
   - opens a `/live` connection.
   Every body and message must contain none of the canary's markers, and no number in an outputs response may have more decimals than the instrument's precision. The JSON keys of an outputs response must be the contract's own (an allowlist), so a new internal field fails the test even without a canary marker.
3. **E2e test** (`apps/web-chart/e2e/leak.e2e.ts`): in the real browser, add the canary indicator and change its settings while recording every HTTP response and every WebSocket frame. Then fetch every built script and stylesheet of the chart. All of it is checked for:
   - the canary markers;
   - the names of engine internals: `IndicatorEngine`, `stepping`, `state-codec`, `init(` and `step(` from an indicator definition;
   - the private repository's name.
   This runs in CI's existing e2e job.
4. **Docs:** architecture (indicator engine, "Leak test"), card handoff.

Not in this task: the real SMA (it lives in the private repository and never reaches public CI; the canary stands in, as `settingsDemo` does).
