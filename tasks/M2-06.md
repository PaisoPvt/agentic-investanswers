# M2-06 Scroll-back paging, smooth loading of older history

## Plan
What I found:
- **API:** the History API already pages backwards. `GET /bars?before=<time>` returns the page before that bar, and `next` is the cursor, `null` once the first stored bar is reached. No server change is needed.
- **Chart:** it loads only the newest page and tells KLineChart there is nothing older (`chart-feed.ts`).
- **KLineChart 10.1's naming is reversed:** the load that prepends **older** bars is type `forward`, triggered when the left edge comes into view, and `backward` appends newer ones. It keeps the view anchored to the right when bars are prepended, so the screen doesn't jump. A load that is never answered blocks every later load, so every request must be answered, even when it fails or is stale.
- **e2e server:** it has only 30 days of made-up history, not enough for the 2-year check.

Steps:
1. **`BarSeries`:**
   - add `loadOlder()`, which fetches the page before the oldest loaded bar (1,000 bars, the API's cap) and prepends it, and `hasOlder` (false once `next` is `null`);
   - one older load at a time;
   - a stale answer, after a switch or a reload, is dropped;
   - a quiet reload keeps the older pages already loaded; a full reset goes back to the newest page;
   - Vitest tests.
2. **`ChartFeed`:**
   - the first load tells KLineChart whether there is older history;
   - a `forward` request calls `loadOlder()` and hands the bars over;
   - on failure, it answers with no bars and waits 5 s before it asks the server again, so a failing request isn't repeated every frame;
   - a stale answer gets an empty reply;
   - Vitest with a fake chart.
3. **`PlatformClient.history`:** takes `before`.
4. **Indicator line on older bars (optional):** the SMA is fetched for the newest 500 bars, so after scrolling back the line stops at the left. The layer would ask for as many points as there are bars on the chart, up to the outputs API's 2,000, and ask again after an older page arrives. Beyond 2,000 bars the line still stops; going further needs a `before` on the outputs route, a contract change and a follow-up.
5. **e2e:**
   - the e2e server gets 2 years and a month of made-up history, generated on demand as now;
   - new `scroll-back.e2e.ts` on BTC 1h: one real mouse drag loads an older page, then the test scrolls to the left edge until no more loads come;
   - checks: the oldest bar is at least 2 years back and is the first stored bar; every step between bars is exactly 1h (no gaps, no duplicates); no requests after the start of history; live updates still land on the newest bar.
6. **Docs:** the chart section of `architecture.md`, the card handoff.

Not in this task:
- a loading spinner for older pages; KLineChart has none built in, and each page arrives in well under a second;
- daily, weekly and monthly timeframes, and stocks (M1-08).
